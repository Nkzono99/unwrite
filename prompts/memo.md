# 段落メモの指示（LLM 用）

あなたは AI が書いた論文草稿を読み、**人間の著者が自分の文で段落を書き直すためのメモ**を段落ごとに作る。
著者はメモだけを見て書く。メモは

- それだけ読んで内容が分かること（電報体に圧縮しない。普通の言葉で説明する）
- 草稿の文や言い回しが著者の文章に移らないこと（草稿の文を写さない、草稿の決まり文句を使わない）
- 論文に要る情報が落ちないこと（数値・引用・参照・条件・論理）

を同時に満たす。節と段落の構成は残す（段落 ¶ の単位は unwrite が決める）。

入力は `unwrite segments <target> [--section N]`。`--- ¶3` の行が段落の区切りで、`¶3b` は式や図の後の続き。
出力は JSON（`memos.json` か部分ファイル）。`unwrite lint` がエラー 0 になるまで直す。

## 形

```json
{
  "unwrite": 1,
  "memos": [
    {
      "slot": "4",
      "point": "クレーターが大きいほど底の電位は下がるが、半径が光電子シースの厚さを超えるとそれ以上は下がらない。",
      "items": [
        {"text": "底の電位は半径とともに負の側へ深くなる（図）", "atoms": {"labels": ["fig:pot"]}, "source": ["s017", "s021"]},
        {"text": "半径が Debye 長の 10 倍のとき、底は \\floorPot V",
         "atoms": {"numbers": ["\\floorPot", "10"]}, "source": ["s018"]},
        {"text": "半径がシースの厚さを超えると下がり方が頭打ちになる", "source": ["s019"]}
      ],
      "role": "¶3 の計算設定を受けて最初の結果を出す。頭打ちになる理由が次の段落の話題になる。",
      "source": ["s017", "s018", "s019"]
    }
  ],
  "dropped": [{"source": ["s020"], "reason": "filler"}]
}
```

## 各欄

- `slot`: 段落の番号（`3`, `3b` …）。1 段落に 1 つのメモ。
- `point`（言いたいこと）: この段落で読者に分かってほしいこと。著者に口頭で説明するつもりで 1〜2 文、160 字まで。
  段落の要約ではなく、段落の**主張**を書く。
- `items`（材料）: 段落に入れるべき事実・根拠・条件・数値・引用・定義。1 項目に 1 つのこと、90 字まで。
  - メモ調（常体。体言止めも可）で、それだけ読んで意味が分かるように書く。記号だけの電報体にしない。
  - 草稿の 1 文に 1 項目でなくてよい。まとめても分けてもよいが、情報（条件・比較の向き・理由）は落とさない。
  - `source`: その項目の元になった文 ID。図表の caption（`[float ...]`）は、その図を説明する段落の項目の source に入れる。
  - `stance`: 草稿が推測・ぼかし・引用として書いているものは `speculative` / `hedged` / `cited`。断定は省略（`asserted`）。
  - `atoms`: 逐語で使うもの（下）。
- `role`（流れ）: 前後の段落とのつながり。何を受けて、次の段落に何を渡すか。120 字まで。
- `source`: この段落の文 ID をすべて。
- `dropped`: 情報を持たない文だけ（`filler` / `signpost` / `restatement` / `meta`）。数値・引用・参照を含む文は落とせない。

## 書き方の注意

- **草稿の文を写さない**: 草稿と 20 字（英語 10 語）以上そのまま同じ並びはエラー（`memo.copy`）。
  自分の言葉で、内容を説明する。ただし専門用語や名詞句（「クレーター底の表面電位」など）は
  無理に言い換えない。不自然な言い換えは、それ自体が別の AI の言い回しになる。
- **草稿の修辞を持ち込まない**: 「重要な役割を果たす」「〜と言えるでしょう」「注目すべきは」「様々な」のような
  決まり文句・評価語は使わない（`memo.eval`）。強調したいことがあれば、その理由（数値・比較）で書く。
- 論理（〜なので、〜だが、〜に対して）は普通に書いてよい。メモの目的は内容を伝えることなので。

## atoms（逐語で持つ）

`numbers`（数値。数値マクロはマクロ名で `"\\floorPot"`）、`eqs`（式の TeX）、`refs`（引用キー）、`labels`（`\ref`・`\label` のキー）。
**段落の文に出てくる数値・数値マクロ・引用キー・ラベルは、その段落のどれかの項目の atoms に必ず入れる**（`atoms.lost`）。
項目の `text` の中では数値を普通に書いてよい（`\floorPot` と書けば値で表示される）。

## 部分ファイルで作るとき

1. `unwrite segments <target> --section N` で担当の節を読む。
2. `part-X.json`（`{"unwrite": 1, "memos": [...], "dropped": [...]}`）に書く。
3. `unwrite lint <target> --part part-X.json --section N` でエラー 0 にする。warn は判断する。
4. チャットに草稿の文やメモの中身を書かない。件数と lint の結果だけを報告する。
